// what it is

You're talking to one assistant. You've also installed and logged into others — Claude Code, Codex, Gemini, opencode, Ollama. cli-bridge connects them: when your assistant needs a capability it doesn't have, it spawns each vendor's official CLI, exactly as you would by hand — never an API key, never a stolen token, so accounts can't get flagged. Reviews fan out to a role-diverse council in parallel and come back merged, deduped and severity-ranked.

// the four levers

Everything cli-bridge does is one of these four moves — each a single tool call from whatever host you're in.

borrow

Reach a model with a bigger context window, vision, or a tool yours lacks — without leaving your assistant.

ask_gemini · ask_lane · images=
spread

Ask several vendors the same thing in parallel; answers return merged and severity-ranked. Different training data → uncorrelated blind spots.

ask_all · review_diff · consensus
offload

Delegate a whole build to a cheaper model. It works in a throwaway git worktree and hands back a diff you review before applying.

ask_build · workflow verify_repair
verify

Pressure-test a conclusion before you ship: an independent skeptic, a cross-vendor jury, a multi-round debate, or a governance loop that converges only once the peers approve.

challenge · jury · converge · debate

// why this one

The space is crowded. cli-bridge's bet is narrow and defensible.

Ban-safe by design

Spawns official CLIs. No OAuth-token extraction, no key reuse — nothing that gets accounts flagged.

Cost governance

Free-first councils, sourced per-plan tiers, and a hard daily credit cap enforced at spawn — spend is bounded by design, with local receipts.

Safe diff-builds

Build agents run in a throwaway git worktree and hand back a diff. Your live repo is never touched.

Cross-vendor governance

Author and reviewer are forced onto different vendor families — a k-of-N jury, or the converge loop (blind arbiter verdict, reasoned dismissal, no self-approval), so correlated errors can't rubber-stamp each other.

Survives /compact

Round-table threads, jobs and fan-out journals persist in sqlite — across host context resets and restarts.

Measured, not asserted

cli-bridge eval tests the council-vs-single claim deterministically and publishes the result either way.

// the honest part

"More models = better" is fragile — big models share training data, so their errors correlate. We measured our own claim: a diverse council did not catch more bugs than one strong model — it cut false alarms ~2×. The numbers are in BENCHMARKS.md, and the harness ships so you can run it on your own CLIs.
